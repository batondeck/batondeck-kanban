# ADR-0003 Layers and contracts: store, service and transports, each in its package, with a guard

- Status: accepted
- Date: 2026-10-23
- Raised by: the owner ("A software should be built in layers. Are we doing it?"; "multiple layers can also be build concurrently if the contract between them is clear"; "recalibrate the whole plan once the layering is done … make sure you account what's built in this new plan")
- Deciders: the owner (2026-10-23, in chat) / the orchestrator

## Context
The import graph measured on `main` at 0e958b4: `internal/domain` imports nothing internal; `internal/store` imports `migrations`; `internal/core` imports nothing internal; `internal/cli` imports `core`, `store`, `web`; `contract/` imports nothing internal. Nothing guards those edges. There is no service layer, although plan §Architecture says the transports "call services directly": as written, R0.8, R0.9, R0.10 and R1.1 would each compose store and domain themselves — the version check, the event, the audit row, the change-log row and the idempotency replay written up to four times, and the role and grant checks living in the MCP middleware where REST could not reuse them. Three in-flight tasks (P-38, R0.8, R0.12) and nine done ones (R0.0–R0.7, R0.16) already conform to the layering below; nothing built is lost.

## Decision
The code is built in five layers, bottom to top, and the guard refuses an import against the direction. Layer 0 is `internal/core` (config as the only env reader, lock, keyring, adminsock, log) and `internal/domain` (pure rules plus `domain.Caller`); they import nothing internal, and `domain` imports no SDK and no `database/sql`. Layer 1 is `internal/store` (one interface per area, CRUD plus compare-and-set with `expectedVersion` → `domain.Stale`, engine statements, `Atomically`) with `sqlitedb`, `pgdb`, the test-only `memstore` and the `conformance` battery, plus `migrations`; layer 1b is `internal/bus` and `internal/retention`. Layer 2 is `internal/service` — the application layer where each rule lives once: `service.mutate` is the only composition of load → version check → fn → bump → `task_events` append → audit row via `domain.DescribeAudit` → change-log row with token scope → idempotency replay, all inside `store.Atomically`, so the change-log row is written inside the transaction and bus-visible after commit; `service.authorize` is the only membership, role-tier and `domain.CheckGrant` check, cached 60 s; the doorbell rows, the caches (board snapshot by cursor, grants, `tools/list` memo), the feed service and the agent/wake session touch live here. `internal/auth` (+`oauth`) and `internal/blob` sit beside it. Layer 3 is the transports — `internal/mcp` (+`tools/`), `internal/api`, `internal/wake` — which import `service`, `auth`, `bus`, `domain`, `core` and never a store package or each other. Layer 4 is `internal/cli` and `cmd/`, the composition root. `contract/` non-test code imports nothing internal. Each boundary has one contract artifact: `internal/domain` itself (B1, `domain.Caller`); `internal/store/contract_<area>.go` with `conformance/conformance_<area>.go` and `memstore` judged by the same `conformance.Run` (B2); `internal/service/contract_<area>.go` with DTOs, a `Services` bundle and `servicefake` (B3); `internal/auth/contract.go` `Resolver` with `authfake` (B4); `bus.Bus{Subscribe, Replay}` (B5). A contract file changes only in its own task, additively within a release; a rename is a new task. `internal/arch/layering_test.go` runs `go list -json ./...` once and asserts the eight rules of the recalibration spec §C as a `make check` step `arch`. **Amended 2026-10-23 (R0.17):** rule 2 forbids a database driver (`database/sql`, modernc sqlite, pgx, goose) only when a package reaches it by an import chain that avoids every `internal/store/...` and `migrations` package; reaching a driver THROUGH the store is the layering working, so `auth`, `service`, `bus` and `retention` importing `internal/store` pass, and a direct driver import outside store/migrations/cli/cmd still fails.

## Consequences
- Tasks R0.17 (the guard), R0.18 and R0.19 (the store contracts), R0.20 (the service contract), R0.21 (the service core), R1.16, R1.17 (the projects/boards/feed and context services) and R1.18 (the join on both engines) are added.
- R0.9–R0.11, R0.13–R0.15 and R1.1–R1.11 are re-pointed: store tasks implement interfaces that already exist, tool tasks map DTOs to a service through `servicefake`, and every proof that needs the real stack moves to R1.18. R1.3 becomes the tasks service and R1.5 the lifecycle service.
- R0.8 and R0.12, in flight, own the store contracts of their areas and the caller/resolver contract; R0.18 and R0.20 take the rest.
- Nothing built is discarded: all nine done tasks conform. The plan of record is unchanged; this ADR is the amendment, cited by every task it touches.
- Harder: three fakes (`memstore`, `servicefake`, `authfake`) to keep honest — `memstore` by the engines' own battery, `servicefake` by R1.18 re-running every transport test on the real service.

## Alternatives considered
- Composition in the store — the audit row needs the operation name and the caller, which the store does not know; REST would duplicate it.
- No fake — serialises every service lane behind the store lanes.
- A second fake for the transports instead of the real service over `memstore` at the join — a fake that lies, since nothing would ever prove the two agree.
